# 유튜브 주간 업로드 보고 봇

매주 일요일 0시(한국시간)에 지난 1주일간 업로드된 영상을 자동으로 정리해서
디스코드 채널에 보고 메시지를 올려줍니다. **서버를 계속 켜둘 필요 없이**,
GitHub Actions가 정해진 시각에만 잠깐 실행되고 끝나는 방식이라 완전 무료입니다.

채팅창에 아래 순서로 메시지들이 올라옵니다:

1. `# 📅 8월 3주 주간 보고` — 제일 크게 뜨는 헤더
2. 👤 본채널 — 롱폼/쇼츠 **영상마다 메시지 1개씩**(채널 프로필 사진 포함), 롱폼은 썸네일
   미리보기도 함께. 업로드가 하나도 없으면 안내 메시지 1개만 뜸.
3. 🎮 봉풀주 — 짧클립/풀영상은 목록으로 묶어서 메시지 1개, 쇼츠만 영상마다 메시지 1개씩
4. 📊 Total — 개수 요약

**담당자 표시 방법 (자동 확정)**: 롱폼/쇼츠 영상 메시지에는 봇이 미리 🅰️/🅱️ 이모지를
달아놨습니다 (메시지 하단에 어떤 이모지가 누구인지 적혀있음 — 롱폼은 🅰️=카페인/🅱️=멜로크론,
쇼츠는 🅰️=박정현/🅱️=상상). 담당자의 이모지를 누르면 **최대 5분 안에** 봇이 자동으로 감지해서
메시지를 "✅ 확정: 이름"으로 바꾸고 이모지를 지웁니다 (별도 폴링 작업이 5분마다 확인하는 방식이라
즉시는 아니고 약간의 지연이 있습니다). 그 외 메모를 남기고 싶으면 메시지를 우클릭 →
"스레드 만들기"로 직접 스레드를 시작해서 적으면 됩니다.

영상 제목을 클릭하면 바로 유튜브 영상으로 연결됩니다.

---

## 준비물 4가지

1. **유튜브 API 키** (무료)
2. **디스코드 웹훅 URL** (무료)
3. **디스코드 봇 토큰 + 채널 ID** (무료) — 이모지 반응을 미리 달아두려면 필요
4. **GitHub 계정** (무료, 이미 있다고 가정)

아래 순서대로 따라 하면 됩니다.

---

## 1단계. 유튜브 API 키 발급

1. https://console.cloud.google.com/ 접속 (구글 계정으로 로그인)
2. 상단에서 "새 프로젝트" 만들기 (이름은 아무거나, 예: `youtube-report`)
3. 왼쪽 메뉴 → **API 및 서비스 → 라이브러리** 이동
4. 검색창에 `YouTube Data API v3` 검색 → 클릭 → **"사용"** 버튼 클릭
5. 왼쪽 메뉴 → **API 및 서비스 → 사용자 인증 정보** 이동
6. 상단 **"+ 사용자 인증 정보 만들기" → API 키** 클릭
7. 생성된 키 문자열을 복사해서 메모장에 잠깐 저장해두기 (예: `AIzaSy...`)

> 무료 쿼터로 충분합니다. 이 봇은 매주 1번, 채널당 API 호출 몇 번만 하므로
> 무료 한도(하루 10,000 유닛)에 전혀 걸리지 않습니다.

---

## 2단계. 디스코드 웹훅 URL 만들기

1. 보고를 받고 싶은 디스코드 채널로 이동
2. 채널 이름 옆 **톱니바퀴(채널 설정)** 클릭 → **연동 → 웹후크**
3. **"새 웹후크"** 클릭 → 이름/아이콘 원하는 대로 설정
4. **"웹후크 URL 복사"** 클릭 → 메모장에 저장

> ⚠️ 이 URL은 비밀번호처럼 취급해야 합니다. 다른 사람에게 노출되면
> 그 사람이 여러분 채널에 마음대로 메시지를 보낼 수 있습니다.

---

## 3단계. 디스코드 봇 토큰 + 채널 ID 준비

웹훅은 이모지 반응을 미리 달아둘 권한이 없어서, 롱폼/쇼츠처럼 영상마다
🅰️/🅱️ 반응이 필요한 메시지는 **봇 토큰**으로 보냅니다.

**3-1. 봇 만들기**

1. https://discord.com/developers/applications 접속 → **"New Application"** 클릭 → 이름 입력(예: `유튜브 보고 봇`) → Create
2. 왼쪽 메뉴 **"Bot"** 클릭 → **"Reset Token"**(또는 바로 보이는 토큰) 클릭 → 토큰 복사해서 메모장에 저장
   (토큰은 딱 한 번만 보여줍니다. 놓치면 다시 Reset Token 하면 됩니다.)
3. 같은 Bot 페이지에서 **"MESSAGE CONTENT INTENT"** 는 꺼둬도 됩니다 (이 봇은 메시지를 읽지 않고 보내기만 함)

**3-2. 서버에 봇 초대**

1. 왼쪽 메뉴 **"OAuth2" → "URL Generator"** 클릭
2. **SCOPES**에서 `bot` 체크
3. 아래 **BOT PERMISSIONS**에서 `Send Messages`, `Add Reactions`, `Embed Links`, `Manage Messages` 체크
   (`Manage Messages`는 담당자 확정 후 이모지 반응을 지우는 데 필요합니다)
4. 맨 아래 생성된 URL을 복사해서 브라우저 주소창에 붙여넣기 → 봇을 초대할 서버 선택 → 승인

**3-3. 채널 ID 복사**

1. 디스코드 앱에서 **설정(톱니바퀴) → 고급 → "개발자 모드"** 켜기
2. 보고를 받을 채널을 우클릭 → **"채널 ID 복사"**

## 4단계. GitHub 저장소에 코드 올리기

이 폴더(`youtube-weekly-report`)를 GitHub 저장소로 만듭니다.

```bash
cd youtube-weekly-report
git init
git add .
git commit -m "유튜브 주간 보고 봇 초기 설정"
```

GitHub 웹사이트에서 새 저장소를 **Public**으로 만든 뒤, 안내되는 명령어로 push 합니다.

> ⚠️ **꼭 Public으로 만들어야 합니다.** 담당자 반응을 5분마다 확인하는 자동화가 있는데,
> Private 저장소는 GitHub Actions 무료 사용량이 월 2,000분뿐이라 5분 간격 폴링은 금방
> 초과합니다. Public 저장소는 Actions 사용량이 무제한 무료입니다. (API 키·토큰은 코드가
> 아니라 GitHub Secrets에 암호화 저장되므로 Public이어도 안전합니다.)

```bash
git remote add origin https://github.com/내계정/youtube-weekly-report.git
git branch -M main
git push -u origin main
```

## 5단계. GitHub에 비밀 키(Secrets) 등록

절대로 API 키나 토큰을 코드 안에 직접 적지 않습니다. 대신 GitHub의
"Secrets" 기능에 안전하게 저장합니다.

1. GitHub에서 방금 만든 저장소 페이지로 이동
2. **Settings → Secrets and variables → Actions** 이동
3. **"New repository secret"** 클릭해서 아래 4개를 각각 등록:

| Name | Value |
|---|---|
| `YOUTUBE_API_KEY` | 1단계에서 복사한 유튜브 API 키 |
| `DISCORD_WEBHOOK_URL` | 2단계에서 복사한 디스코드 웹훅 URL |
| `DISCORD_BOT_TOKEN` | 3-1단계에서 복사한 봇 토큰 |
| `DISCORD_CHANNEL_ID` | 3-3단계에서 복사한 채널 ID |

(유튜브 채널 ID는 비밀 정보가 아니라서 `report.py`에 본채널/봉풀주 채널 ID가
이미 기본값으로 들어가 있습니다. 다른 채널로 바꾸고 싶으면
`.github/workflows/weekly-report.yml` 안의 주석 처리된 두 줄을 풀어서
채널 ID를 넣으면 됩니다.)

## 6단계. 정상 작동 확인 (수동 실행)

일요일까지 기다리지 않고 지금 바로 테스트해볼 수 있습니다.

1. GitHub 저장소 페이지 → 상단 **"Actions"** 탭 클릭
2. 왼쪽에서 **"유튜브 주간 업로드 보고"** 워크플로 클릭
3. 오른쪽 **"Run workflow"** 버튼 클릭
4. **"테스트용 기준 날짜"** 입력칸이 나옵니다. 그냥 비워두면 실제 이번 주 기준으로 돌아가고,
   특정 주(예: 8월 1주, 8/2~8/8)를 보고 싶으면 그 다음 일요일 날짜를 넣으면 됩니다
   (예: `2026-08-09` → 8/2~8/8 결과가 나옴)
5. **"Run workflow"** 클릭
6. 30초~1분 정도 후 디스코드 채널을 확인 → 메시지들이 순서대로 올라와 있으면 성공!

실행이 빨간색(실패)으로 뜨면, 그 항목을 클릭해서 로그를 확인하세요.
대부분 키/토큰을 잘못 붙여넣은 경우입니다.

## 이후에는?

워크플로 2개가 각자 알아서 돌아갑니다. 아무것도 더 안 하셔도 됩니다.

- `weekly-report.yml` — 매주 토요일 15:00 UTC(= 일요일 00:00 KST)에 주간 보고 전송
- `poll-reactions.yml` — 5분마다 실행되어, 담당자 이모지 반응이 달렸는지 확인하고 확정 처리

## 분류 기준 (재생목록 기반)

**모든 영상을 재생목록 소속으로 분류**합니다 — 즉, 새 영상을 올리면 그때그때
알맞은 재생목록에 넣어줘야 보고서에서 제대로 분류됩니다.

**본채널** — 쇼츠 재생목록에 있으면 쇼츠, 없으면 롱폼

- 쇼츠: `MAIN_SHORTS_PLAYLIST_ID` (기본값 `PLqE7uvTHaH30qYSSVmxsjV6JrlUUInv_f`)

**봉풀주** — 쇼츠 재생목록 → 짧클립 재생목록 → 풀영상 재생목록 순서로 확인
(**셋 중 어디에도 없으면 보고서에서 제외** — 반드시 재생목록에 넣어줘야 집계됨)

- 쇼츠: `SUB_SHORTS_PLAYLIST_ID` (기본값 `PLQCedlY19W03Zpo5l4MYInmwqiqJQnO75`)
- 짧클립: `SUB_CLIP_PLAYLIST_ID` (기본값 `PLQCedlY19W00gv3uJ7OP_kqYQ-l2kFjQE`)
- 풀영상: `SUB_LONG_PLAYLIST_ID` (기본값 `PLQCedlY19W03t8VSqAeRTleKHzXfSZpB7`)

재생목록을 바꾸고 싶으면 `.github/workflows/weekly-report.yml`에 같은 이름의
env 값을 추가해서 덮어쓰면 됩니다(채널 ID와 동일한 방식).
